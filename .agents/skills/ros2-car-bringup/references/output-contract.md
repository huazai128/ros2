# 后续 AI 输出契约

本文件适用于这个项目中所有面向用户的 AI 回复、代码注释、运行文档和故障报告。

## 必须包含

1. **先给结果**：首句说明完成状态、发现的关键问题或当前阻塞。
2. **边界清晰**：区分“已验证”“静态检查通过”“尚未在真实小车验证”。没有硬件证据时不得称为已上车成功。
3. **可执行用法**：涉及操作时给出可复制命令，并保留 `<占位符>`；说明命令运行在哪台机器（Mac 或小车）。
4. **验收与下一步**：每项操作说明可观察的通过结果；只有满足前置条件才给出下一阶段。
5. **改动可追踪**：代码或配置变更列出文件绝对路径、改变的行为和运行过的验证；失败测试也要说明。
6. **安全信息**：凡涉及电机、供电或自动导航，提示急停、低速和人员监护；不要远程自动驱动车辆。
7. **同步状态**：发生项目文件改动时，最终回复必须报告 `scripts/sync_to_ubuntu.sh` 的成功或失败状态；同步不能替代 Ubuntu 上的编译或实体车验证。

## 写作规则

- 使用简体中文，技术名、话题、frame、文件名和命令保持原样。
- 简洁、可扫描；优先短段落和有标题的清单，不用无依据的泛泛说明。
- 命令必须可复制，代码块前写清执行位置。不要混淆 Mac 本机与车载 Ubuntu。
- 问题诊断按“现象 → 已知证据 → 最小下一检查 → 通过条件”输出。
- 修改请求按“完成内容 → 文件 → 验证 → 尚需用户操作”输出。

## 禁止事项

- 不杜撰设备型号、串口、IP、驱动包、topic、frame、测试结果或地图路径。
- 不跳过阶段、不在缺少安全条件时建议执行运动命令。
- 不把静态语法检查描述为 ROS 集成测试或实体车测试。
- 未经用户明确授权，不执行破坏性删除、系统级安装、网络暴露、远程发布或真实电机运动。
